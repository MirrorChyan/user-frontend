# Mirror酱首页布局原型

打开 `index.html` 即可预览。所有页面、脚本、样式和应用图标都在此目录，不依赖前端构建或在线 CDN。

也可在仓库根目录运行：

```powershell
python -m http.server 4173 --bind 127.0.0.1 --directory preview/layout-lab
```

然后访问 <http://127.0.0.1:4173/index.html>。

## Phase 1 选择

用户已选择首页 A 与 Projects A1。正式实现位于 `src/components/design-a/`，接入现有 `page_group=b`；`a` 保留原版作为对照。B / C / D 及 Projects A2 / A3 文件继续保留为备选，没有接入运行时分流。代码已实现，尚未部署或调整远程分流权重。品牌 slogan 与完整产品介绍继续沿用原文。

## 四个首页方向

| 原型              | 视觉与布局                                                 | 要验证的假设                                         |
| ----------------- | ---------------------------------------------------------- | ---------------------------------------------------- |
| `a.html` 套餐直达 | 蓝白色、居中标题、三档套餐、明显的年卡重点；手机端年卡置前 | 已经了解服务的访客，更早看见套餐是否更容易进入收银台 |
| `b.html` 应用优先 | 米白与森林绿、应用目录与搜索在前、紧凑套餐列表在后         | 访客先确认自己的应用已接入，是否更愿意选择套餐       |
| `c.html` 极简品牌 | 深墨蓝、醒目的排版、应用到设备的更新流程图、浅色价格列表   | 更清晰的产品认知和品牌呈现，是否有助于订阅决策       |
| `d.html` 分步引导 | 暖灰、左右分栏、单选时长、两步引导、单个主按钮             | 把并列的购买入口收敛为引导步骤，是否减少选择负担     |

评审页支持桌面 / 手机预览、并排对比，以及保存在浏览器本地的候选标记。右上角“单独打开”可打开独立页面。

套餐按钮会显示演示订单摘要。应用卡片可进入套餐选择；B 支持应用搜索；D 支持选择时长、进入下一步与返回。查询 CDK、时长转换有本地演示弹窗。外部文档、源码、完整应用列表、用户协议与交流频道明确链接到正式站点。

## 内容与边界

- 四套方案均保留官网现有 slogan「使用Mirror酱更新你的App」及完整产品介绍，统一引用 `messages/zh.json` 的原文；不以改写品牌文案作为实验变量。仅调整换行、排版、配色和信息结构；新增操作说明使用中性表述。

- 套餐及应用列表取自 2026-11-01 的正式公开接口：`https://mirrorchyan.com/api/misc/plan` 和 `https://mirrorchyan.com/api/misc/project`。本地固定使用月卡 ¥6.9、季卡 ¥12.9、年卡 ¥29.9，应用总数 95，并展示前 9 款应用。它们是原型快照，不会实时更新。
- `assets/projects.json` 保留本次使用的应用名称与图标路径。图标来自项目现有公开目录。
- 没有添加虚构用户评价、测速结果或使用量数据。C 中的图形是更新路径示意。
- 付款、查询、时长转换均为本地演示；不连接支付或 CDK 接口，不发送埋点。请勿在原型中输入真实订单或 CDK。
- 本目录继续作为静态评审原型；正式页面从真实 API 读取数据，分组接法见仓库根目录 README。

## 选定后的测试

这些字母仅是原型编号。现有 `src/config/group.ts` 的 `page_group` 允许 `a`、`b`，已将选定的首页 A 与 Projects A1 映射到技术分组 `b`，`a` 为原版对照；备选设计没有扩展为新的技术分组。

这轮同时探索视觉与信息结构，因此适合先选布局方向，不宜直接把差异归因于某个单独元素。落地时保留当前首页作为对照，本轮仅以 A 方向进入 Phase 1；统一套餐、价格、业务入口和收银台，保持既有 `exp` 曝光与 `plan_click` 的统计口径。移动端顺序和默认选中项也属于需要明确的实验变量，品牌文案保持不变。

可先观察每个曝光访客到 `plan_click` 的转化；付费完成率需要确认收银台至服务端订单的归因链路后再比较。不要仅凭按钮点击量决定胜出方案。

## Projects 页原型

打开 `projects.html`，或访问 <http://127.0.0.1:4173/projects.html>。可以切换桌面 / 手机、并排比较并标记候选；Projects 的候选记录与首页独立保存。

| 文件               | 布局差异                                                         |
| ------------------ | ---------------------------------------------------------------- |
| `projects-a1.html` | 卡片网格：项目简介、平台与下载按钮在同一卡片内，分类和搜索置顶   |
| `projects-a2.html` | 侧栏列表：左侧分类与系统筛选，右侧紧凑项目行；手机端筛选移至顶部 |
| `projects-a3.html` | 列表详情：左侧选项目、右侧查看完整简介后下载；手机端使用详情弹窗 |

三套全部沿用 A 的蓝白风格，不代表首页 B / C / D 恢复参与 Phase 1。使用当前公开目录快照中的全部 95 个项目（88 个应用项目、7 个依赖组件），保留默认顺序、项目名称、简介、官网链接和下载能力。91 个项目使用本地图标，其余使用名称首字作为占位。新增的搜索、分类、系统筛选、分页及项目详情均为本地交互。

下载弹窗根据目录真实的支持组合联动发布渠道、系统和架构，包括带资源前缀与 `@` 展示别名的条目。下载按钮仅展示本地结果，不会验证 CDK、请求真实文件或发送埋点；原有的第三方分发收费说明保留。
